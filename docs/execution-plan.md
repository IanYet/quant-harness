# Quant Harness 首版执行文档

交付一套单机 Bun + TypeScript 的量化交易 harness，首个交易所接币安 USDⓈ-M 永续合约，默认观察 `BTCUSDT`。交易员和 agent 可以随时写一个普通 `.ts` 文件，取数据、观察市场、发通知或运行策略。提交、修改和替换脚本期间，宿主持续接收行情并跟踪账户挂单和成交。

设计基线见[架构图](architecture.svg)。实现完成后，另写 `docs/architecture.md` 描述实际代码、接口和运行方式。

## 1. 从两个脚本跑通

用同一个 `harnessd` 服务完成下面的工作流。

1. 采集脚本订阅 BTC 小时收盘事件，自己用 `fetch` 取一个额外指标，把结果追加到命名数据集。第一次写入即可创建数据集。
2. 策略脚本读取过去 60 天的已收盘小时 K 线预热，随后跟踪新 K 线或上述数据集，在模拟账户提交订单。脚本可以使用任意普通 Bun/TS 依赖，自行决定执行一次、定时运行或持续读流。
3. agent 查日志、改代码，把新版作为观察进程并行运行，再替换同名策略。旧挂单仍可查询，其他脚本继续消费同一份行情。

把两个示例放进仓库，使全新 checkout 能用模拟行情和模拟账户复现这条链路。

## 2. 部署与接口

首版使用一个常驻 `harnessd`、一个项目内可 import 的 `@quant/tools` SDK、若干由 `Bun.spawn` 启动的独立 Bun 脚本进程，以及一个本机 SQLite 文件。宿主包含主 ticker、历史数据、交易、脚本管理、健康检测、通知和 agent connector。代码目录可按实现需要安排。

脚本只交付源码及其依赖。临时研究可直接 `bun run`，托管运行可用 CLI。普通查询和命令走本机 HTTP，事件订阅走一个由脚本发起的 HTTP GET。宿主在同一个响应体逐行发送 NDJSON，SDK 按完整行解码成异步迭代器。脚本 `break`、取消请求或退出时释放监听。低频收盘流处理空闲超时，慢客户端采用有界缓冲，避免拖慢 ticker。部署入口保持普通脚本的使用方式，省去 manifest、回调端口和独立消息中间件。

| 使用方 | 需要交付的能力 |
|---|---|
| `market` | 最新报价、历史 K 线、实时报价和已收盘 K 线。按需查询成交、盘口、资金费率、未平仓量、24 小时统计和合约规格。支持临时跟踪成交或多档盘口 |
| `trade` | `positions`、`openOrders`、`place`、`cancel`、`close`、`setLeverage`，可按返回的 ID 查询交易指令和订单状态 |
| `data` | `append(name, record)`、`read(name, …)`、`watch(name, …)`。记录带稳定游标，便于脚本从已读位置衔接历史与后续追加 |
| `notify` | `send` 接收类型和结构化内容。宿主根据配置选择机器人、接收目标和模板，提供可运行的 webhook 投递路径，记录投递结果 |
| `agents` | `startTask`、`sendMessage`、`getStatus`。按后端名路由，保存任务与远端会话的对应关系。首版交付可配置的 HTTP 适配器，可绑定多个后端，本机测试服务可验证完整请求和响应 |
| `harness` CLI | `run FILE [--name NAME]`、`logs RUN_OR_NAME`、`status`、`stop RUN_OR_NAME`、`replace NAME FILE`。CLI 和 SDK 连接同一个宿主 |

## 3. 主 ticker 与采集口径

基础行情覆盖固定关注的合约及当前有持仓、挂单的合约。额外数据流由正在使用该数据的脚本驱动。同一合约的同一行情流复用一个上游订阅，按币安要求分别接入 public 和 market WS 路径。断线后恢复所需订阅，标记数据缺口。实时推送频率和 SQLite 写入频率分别处理。

| 币安行情 | 内存和触发 | 默认落库 |
|---|---|---|
| `<symbol>@kline_1m` | 更新当前 K 线，以 `k.x = true` 触发收盘。其他周期按交易所边界聚合完整的分钟线，或按需订阅原生周期 | 每根已收盘分钟线写一次，按合约、周期、开盘时间去重。缺失区间走 REST 回补 |
| `<symbol>@bookTicker` | 每条更新买一、卖一的价格和数量 | 每分钟取当时最新值写入市场快照，保留报价自己的来源时间 |
| `<symbol>@markPrice@1s` | 更新标记价、指数价、当时可见的资金费率、下次结算时间 | 与一档报价合写每分钟一条市场快照，保留各自的事件和接收时间。失联或过期须可识别 |
| `<symbol>@forceOrder` | 每条公开强平快照均可供脚本观察 | 收到即存。币安对同一合约每秒最多推送该窗口最后一笔，统计结果按“公开强平快照”标注 |

**历史按需获取。** `market.bars` 先查缓存，只补缺少的区间，默认返回已收盘记录。首次订阅先接流并暂存，再以确定的收盘时间衔接历史，按 K 线键消重。回补行情用于恢复状态，保留与实时触发的区别，避免重放旧信号导致实盘开仓。

近期与历史成交、实际结算资金费率、OI 和多空比支持按合约及时间范围读取。普通历史 OI 接口的回溯窗口约一个月，更早要按官方 `metrics` 日文件的覆盖情况获取。历史成交用 `trades` 或 `aggTrades`，实时成交触发按需接 `@aggTrade`，保留聚合口径。24 小时摘要按需查，交易参数在启动和刷新时取。

**多档盘口按需开录。** 即时深度可直接查快照。需要回放逐档变化时，采集脚本通过 SDK 订阅 `@depth@100ms`，正确衔接初始快照与缓冲增量，保存更新序号。序号断裂后记缺口，重建快照。币安 `bookDepth` 日文件按百分比区间汇总深度，不能用于还原每次逐档更新。

币安协议和字段以[合约 REST 行情](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/rest-api/market-data)、[合约市场事件流](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/ws-streams/market)、[盘口流](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/ws-streams/public)和[历史归档说明](https://github.com/binance/binance-public-data#futures)为准。

## 4. 交易系统独立于脚本

- 同一套交易 SDK 支持本地模拟和币安执行适配器。默认模拟模式可完整验收。交易所密钥和签名由宿主持有，脚本只拿本次运行所需的连接信息。报价、数量和交易所步长按十进制精度处理。
- 接单时持久化业务幂等键、所属策略及运行 ID、订单参数、稳定的客户订单号。重复提交返回原指令结果，相同键携带不同参数应报错。记录策略决策实际使用的报价和来源时间，便于复盘。
- 币安适配器实现签名下单、查询、撤单、平仓、杠杆调整，以及账户私有回报和重连对账。区分已接受、部分成交、完全成交、撤销、拒绝和执行结果未知。请求超时但可能已经发到交易所时，先按原客户订单号及账户回报核对。成交按交易所唯一标识去重。
- 平仓读取实际账户、合约与持仓方向。按币安当前持仓模式执行相应的减少仓位操作，调杠杆作用于对应账户与合约。同一净仓由一个执行所有者控制，其他脚本可观察或使用模拟账户。
- CLI 停止脚本时收回新增交易指令的权限。已有订单继续由宿主跟踪，撤单和平仓通过各自的显式操作执行。宿主重启后从 SQLite 恢复订单状态并对账。

[币安合约交易接口](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/rest-api/trade)和[执行结果未知的处理说明](https://developers.binance.com/en/docs/products/derivatives-trading-usds-futures/general-info)给出具体交易所语义。

## 5. 脚本生命周期、健康与存储

- 每次托管运行自动生成 `runId`，记录实际运行的源码版本或快照、入口、可选名称、模式、开始与结束时间、退出码及日志。agent 可以继续修改工作文件。标准输出和错误输出均可通过 CLI 查看。
- 同名策略换版时，先让候选进程以观察权限启动并读取现有仓位、挂单和需要的状态。切换时由宿主原子交接下单权，交易入口核对当前所有者，随后停止旧进程。候选启动失败时旧版保有下单权。agent 可先运行观察版再决定切换，普通脚本无需实现统一生命周期回调。
- SQLite 保存已收盘 K 线、市场快照、强平快照、命名数据集、订单意图与成交、运行记录、通知与 agent 任务记录。给查询时间范围、数据游标和幂等写入建立相应约束。运行库、凭证、私有日志和行情归档存到可配置的数据目录，Git 只跟踪源码、必要配置示例及文档。
- 健康检查使用独立定时器，观测 WS 连接、最后有效行情、脚本退出、正在对账的未知订单。历史下载、机器人调用和 agent 请求可以失败或重试，其等待时间应与主 ticker 的收包循环解耦。

## 6. 实施顺序与验收

| 顺序 | 实施内容 | 可观察的验收结果 |
|---|---|---|
| 1 | Bun 工程、宿主、SQLite、SDK、HTTP 与 NDJSON | 一个测试宿主可启动。两个普通脚本独立收到同一事件，断开一个后监听被释放，另一个仍能收到下一条。验证跨网络块的 UTF-8 和 JSON 行 |
| 2 | 币安公共行情、四条常驻流、历史回补和按需深度 | 以可重放的交易所消息验证收盘去重、分钟快照、强平口径和深度缺口。查询 60 天 1 小时 K 线得到按时间排列的 1,440 根已收盘记录，连续运行时可新增下一根 |
| 3 | 交易、模拟账户、签名请求与私有回报 | 模拟下单、挂单、成交、撤单与平仓可查。用本机交易所替身验证请求签名、重复下单、已接收但超时、回报重投、重启对账。本次开发验收用模拟执行或测试替身，公共行情可连真实端点抽查 |
| 4 | 运行管理、策略交接、命名数据集 | 从 CLI 跑通第 1 节两个脚本。替换一个策略期间 ticker 和另一个脚本持续运行，旧版本的迟到指令被拒绝。候选启动失败不影响旧版 |
| 5 | 健康、通知和 agent connector | 模拟 WS 断开和脚本异常退出，能查到状态。对本机 HTTP 接收器验证模板、目标、任务启动、发送消息与状态查询 |
| 6 | 实现后的架构文档与交付 | 从干净安装步骤运行类型检查、测试、宿主及示例。写明实际验证过的行为、验证环境和外部服务配置。将源码、锁文件、示例、执行文档、架构文档和图一并提交并推送 |

最终的 `docs/architecture.md` 应让下一位开发者能够根据实际文件定位 ticker、交易适配器、脚本宿主和 SDK。说明一次行情和一次订单各走哪些模块、表与 HTTP 接口，如何运行示例、替换策略、补历史、配置机器人和 agent 后端，并标出模拟验证与实盘环境的差别。架构图如与实际实现有差异，一并更新。

本项目当前远端为 [IanYet/quant-harness](https://github.com/IanYet/quant-harness)，当前分支为 `main`。完成普通推送后，用远端分支的提交 SHA 核对本地 HEAD，并在交付消息中给出提交链接和验证结果。
